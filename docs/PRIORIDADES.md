# Prioridades de entrega

## Ordem recomendada

1. **Preparar o portfólio e seu repositório:** identidade, navegação, README e estrutura de conteúdo. Completar o posicionamento assim que os dados profissionais forem informados. Evitar refinar animações e detalhes decorativos enquanto faltam informações centrais.
2. **Consolidar uma versão demonstrável do Dieta Fácil:** escolher um fluxo de usuário com começo, meio e fim, concluir as regras essenciais, verificar persistência e erros e registrar como reproduzir a demonstração. O escopo dessa entrega deve ser combinado no repositório do Dieta Fácil. Não é necessário concluir todas as ideias do roadmap para apresentá-lo.
3. **Atualizar o estudo de caso:** sua contribuição exata, tela atual, funcionalidades entregues, decisões que consegue explicar, limitações e acesso à demonstração. Integrar currículo e contatos e publicar uma primeira versão do portfólio, mesmo que conte com apenas um projeto sólido.
4. **Construir ou selecionar um segundo projeto:** escolher um problema e competências complementares às vagas desejadas. Concluir uma entrega demonstrável antes de iniciar o terceiro.
5. **Completar a seleção com o terceiro:** o quarto só entra se acrescentar evidência relevante. Remover cartões reservados da versão pública até existir conteúdo real.

## Critério para um projeto entrar no portfólio

- Resolve um problema que pode ser explicado em poucas frases.
- Tem um fluxo principal reproduzível e estado de desenvolvimento claro.
- Sua participação e a origem do trabalho estão descritas com honestidade.
- O código possui instruções suficientes para execução.
- Há evidências proporcionais ao escopo: telas, demonstração, testes relevantes e decisões.
- Você consegue explicar o funcionamento, as escolhas e as limitações.

## Organização do GitHub

- `portfolio`: código e documentação do site pessoal.
- `dieta-facil`: código e documentação do produto Dieta Fácil.
- Cada novo produto tem seu próprio repositório quando for independente.
- Um README de perfil é opcional e usa um repositório com o mesmo nome do usuário, `LuisFernandoRodriguesDePaula`. Não confundir esse repositório especial com o site.
- Fixar os trabalhos mais fortes no perfil após sua revisão; evitar encher a apresentação com repositórios incompletos.

README de cada projeto: problema, estado real, imagem ou demonstração, funcionalidades, tecnologias, execução, validação, estrutura e decisões relevantes. Acrescentar limitações e próximos passos de forma breve. Não usar títulos de senioridade, badges sem validação ou métricas inventadas para aparentar experiência.

Commits devem descrever mudanças reais. Issues e pull requests ajudam quando registram escopo, revisão ou decisões úteis; não precisam ser criados artificialmente para uma alteração simples.
